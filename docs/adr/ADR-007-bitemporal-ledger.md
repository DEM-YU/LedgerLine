# ADR-007: 双时态账本设计（`effective_date` 与 `posted_at`）

状态：已采纳

## 背景

实际记账中，业务发生日期（如 2 月的发票或银行交易）与系统入账时间（如 3 月底或 4 月初才完成补录或冲销）往往不一致。审计和经营复盘需要同时回答“某一业务截止日的财务状况”以及“截至历史上某一天系统已经知道的账务口径”。

## 选项

1. **单时间戳（仅 `effective_date` 或仅 `created_at`）**：无法区分补录/冲销在系统视角下的发生时点，历史期间报表会随后续补录静默变化而无法复现。
2. **双时态字段（`effective_date` + `posted_at`）**：记录业务发生日期与系统入账时间戳，全部财务报表按两个时态参数过滤。

## 决定

采用选项 2：

- `journal_entries` 同时持久化业务生效日期 `effective_date` 与系统入账时间戳 `posted_at`。
- 所有报表 SQL（试算平衡、总账、应收账龄、利润表、资产负债表）在 `REPEATABLE READ` 隔离级别下支持 `as_of_effective` 与 `as_of_posted` 两个截断参数。
- 已关账期间不允许新增或修改分录，冲销分录默认记入当前 `open` 期间。

## 后果

- 优点：可精确复原任意历史入账时点看到的历史期间数据；与只追加账本结合，审计可追溯性完整。
- 代价与限制：报表 SQL 过滤条件与索引设计更复杂；`account_period_balances` 物化余额仅加速最新 `posted_at` 口径，历史 `as_of_posted` 查询仍需回溯明细或对应快照策略，必须通过 `EXPLAIN ANALYZE` 验证查询计划。
