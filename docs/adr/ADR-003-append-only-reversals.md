# ADR-003: 分录只追加，修正统一走冲销分录

状态：已采纳

## 背景

财务与审计要求每笔已入账分录都可追溯，任何误记账或撤销对账匹配都不能通过原地修改或删除记录来抹除历史痕迹。

## 选项

1. **允许草稿修改或管理员软删除/原地更新**：查询简单，但破坏审计轨迹，使历史时点报表和哈希链无法自洽。
2. **严格只追加（Append-only）+ 冲销分录（Reversal Entry）**：数据库触发器彻底拒绝 `journal_entries` 和 `journal_lines` 的 `UPDATE` / `DELETE` / `TRUNCATE`，修正时生成借贷方向相反的新分录并通过 `reverses_entry_id` 关联原分录。

## 决定

采用选项 2：

- 在 `journal_entries` 和 `journal_lines` 上挂载 `forbid_mutation()` 触发器，阻断一切原地变更。
- 冲销分录设置 `source = 'reversal'` 与唯一外键 `reverses_entry_id`，在数据库层面保证同一分录最多被冲销一次。
- 冲销分录默认记入当前 `open` 期间，确保已关账期间的原始历史记录保持静止。

## 后果

- 优点：天然完整保留审计线索，支持双时态历史还原与不可变哈希链校验，测试库也不依赖删除账本行进行清理（改为按模块克隆模板库）。
- 代价与限制：查询“有效/净业务分录”或对账匹配状态时需识别或过滤冲销链；误操作不能静默覆盖，必须产生一条可见的冲销记录。
