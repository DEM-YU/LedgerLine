# ADR-005: 分录号按租户无间断递增

状态：已采纳

## 背景

会计合规与防篡改审计通常要求凭证编号在账套内连续无断号，以便快速识别缺漏记录，同时为租户级哈希链提供严格的全序关系。

## 选项

1. **PostgreSQL `SEQUENCE`**：并发性能好，但事务回滚后序列值不会回退，必然产生断号，也无法直接按租户隔离编号。
2. **租户计数器表 `org_counters` 行锁递增**：在入账事务内执行 `UPDATE org_counters SET next_entry_no = next_entry_no + 1 WHERE org_id = :org_id RETURNING ...`，随业务事务原子提交或回滚。

## 决定

采用选项 2：

- 每个租户在 `org_counters` 中维护单行计数器；入账事务按固定加锁顺序最先锁定并推进该行，同时确定该笔分录的 `entry_no` 与前序 `entry_hash`。

## 后果

- 优点：事务失败回滚时编号同步回滚，保证 `entry_no` 按租户严格连续无洞，哈希链天然单链有序。
- 代价与限制：同一租户的并发入账在写路径上串行化（不同租户互不阻塞）。需通过真实并发基准压测（目标 20 并发 `p95 <= 50 ms`）量化记录该锁竞争延迟。
