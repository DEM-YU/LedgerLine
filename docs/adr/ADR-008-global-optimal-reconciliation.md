# ADR-008: 自动对账采用连通分量全局最优分配而非贪心匹配

状态：已采纳

## 背景

银行流水与未结发票之间存在金额相近、日期接近、摘要模糊甚至多对多候选竞争的场景。如果按单一排序逐条贪心锁定高分对，前面的局部次优选择可能抢占关键候选，导致后续流水无发票可配或错配。

## 选项

1. **按最高分排序的贪心匹配**：实现直接、速度快，但在金额相同、日期交错的竞争组中容易产生局部最优陷阱。
2. **分块候选 + 二部图连通分量切分 + 匈牙利算法全局最优分配**：按 `(org_id, amount_cents, date)` 索引窗口与引用号生成稀疏候选图，拆分为独立连通块后在每块内运行 `scipy.optimize.linear_sum_assignment` 求总分最大匹配；对同客户一对多核销使用受限子集和搜索（meet-in-the-middle，候选 `<= 20`、每组 `<= 5` 张）。

## 决定

采用选项 2：

- 保持评分函数完全基于可解释特征（金额差、日期差、`rapidfuzz` 描述相似度、引用号命中、`payee_hints` 历史先验），不引入黑盒机器学习模型。
- 按高/低阈值将分配结果分流至 `auto_accepted`、`needs_review` 或未匹配，确保高风险边界进入人工队列。
- 通过固定随机种子合成数据集及噪声注入，量化对比全局最优分配与贪心基线的 Precision / Recall / F1 及 `auto_accepted` 准确率。

## 后果

- 优点：解决竞争候选下的全局匹配冲突，评分逻辑完全可解释，可通过网格搜索与评测集持续调优阈值。
- 代价与限制：必须严格通过索引分块与连通分量规模控制求解复杂度（超大连通块或超限一对多候选直接转人工处理），避免 `O(n^2)` 建图或指数爆炸。
